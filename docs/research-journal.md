# Research journal and spot execution costs

This feature targets the current Neon app. It adds research and costs for spot stocks/ETFs and crypto accounts; leveraged positions and Supabase rollback mode retain their existing execution models. Production migration, merge and deployment were separately authorized by the owner on September 30, 2026. See [release recovery reference](research-release-rollback.md) for release order and application rollback without discarding later records. Production test trades, account resets and credential creation are excluded.

The existing Vercel GitHub integration built a preview automatically for the initial feature push. No deployment command or production promotion was invoked. Automatic deployments are now disabled for the exact `feat/research-journal-costs` branch in `vercel.json`, preserving other branch behavior.

## Research workflow

Open an account’s **Research & review** tab. Preserve a plan before execution: hypothesis, strategy version, entry and exit conditions, expected holding days and position sizing. For the SPY/XLF/XLE workflow, use the actual 2–5 trading-day expectation and a named strategy version. `NO_TRADE` preserves the reason for abstaining and cannot link to a fill. Recording research never places an order.

Plans use a server timestamp and cannot be rewritten by the app role. Reviews append separate timestamped records. Link later matching spot transactions from the same account/symbol; a transaction can belong to only one plan. A link includes the full ledger snapshot. Plans/reviews/links survive reset. Account deletion nulls the account reference and retains its name; ledger deletion nulls the live transaction reference while preserving the snapshot. Archived plans remain accessible through `get_research_journal` without `account_id` or authenticated `GET /api/research` without `accountId`. The existing unstructured Supabase `journal_entries` are left intact: they are not retroactively represented as pre-trade hypotheses or silently imported.

Cookie-authenticated JSON API: `GET /api/research?accountId=UUID`; `POST /api/research` with `{requestId, command}`. POST requires same origin. Commands are validated in `src/lib/research-input.ts`: `PLAN`, `REVIEW`, `LINK`, `PROFILE`. UI and the five new MCP tools invoke the identical atomic SQL boundary and preserve retry UUIDs. Existing token ownership/auth checks still apply; no new tokens are needed.

## Cost accounting

Default: zero explicit fees, zero spread and zero slippage. Many stock/ETF brokers have zero commission; choose the assumptions appropriate to the broker and account asset class rather than treating every stock trade as commission-bearing. Profiles are account scoped, named, configurable through UI/MCP, and affect future spot market and limit fills, including already pending orders. An executed transaction preserves its applied profile, reference quote, fill price, explicit fee, spread/slippage cost and quote observation time. Changing a profile cannot recost an execution or alter a successful retry receipt.

For each fill, explicit fee is `max(minimum_fee, fixed_fee + per_unit_fee * quantity + filled_notional * fee_bps / 10000)`, rounded to eight decimals. Modeled half spread and adverse slippage shift each unit price up on BUY and down on SELL. They are embedded in notional and reported separately, not charged again as explicit fees. A buy debits notional plus fees and adds both to weighted-average basis. A sell credits notional less fees; its realized P&L uses the prior weighted-average fee-inclusive basis. Open P&L uses current marks versus that basis and excludes future exit costs. UI dollar budgets/Max include explicit fees and adverse price assumptions; estimates may move with the execution quote or a concurrently changed profile, so the locked SQL balance check is authoritative.

Market fills and MCP share `quoted_spot` and `command`; limit checks/background service wrappers call the same `command`. Limits wait unless the final modeled fill price meets the limit. Fees are separate and can increase buy cash beyond the price × quantity limit. Fills and ledger writes remain in the same database transaction. Failed insufficient-funds market fills roll back; permanently unaffordable triggered limit orders are canceled through the existing policy.

The review reads all available spot ledger rows since the latest reset. New sells store authoritative net realized P&L. Older sells are reconstructed only if basis can be recovered; unknown-basis sales are excluded and counted. Profitable-sale counts describe execution slices, not independent strategy round trips. Cost totals include fees on still-open holdings; do not subtract totals again from realized P&L. The performance chart uses available daily snapshots and a ^GSPC price-return benchmark over matching dates, with daily cash-flow-adjusted chained portfolio returns. It now starts after the latest reset day, excluding that day because snapshot timing is unknown. Intraday cash-flow timing is approximate; the whole account, including leveraged positions, affects snapshots. There is no fabricated pre-snapshot history, credited dividend return or risk-matched SPY/XLF/XLE comparison. Backtest cost estimates remain separate and unchanged.

## Migration and release

Generate the reviewable **atomic, additive** production SQL locally:

```powershell
node scripts/prepare-research-upgrade.mjs --production
```

This writes ignored `neon/research-upgrade-live.sql` and never connects to a database. It combines `research-costs.sql`, `trading-engine.sql`, and `orders-engine.sql`, rewriting only fixed schema/role identifiers to `poshkan_live` / `poshkan_live_app`. For rehearsal, omit `--production`. Apply the generated SQL only to the corresponding already-installed Neon schema after separate release approval and backup. Existing `actor`, `owns_account`, `completed`, accounts, requests, and order tables are prerequisites. Run the whole transaction, not just individual snippets. Review new-table SELECT/EXECUTE grants and RLS; no app role receives direct journal or profile mutations. PUBLIC cannot invoke the new functions. Existing service wrappers retain their execution grants. The migration can be rerun and does not rewrite historical prices, cash, positions, or P&L. New historical cost columns default to zero; reference/profile/time/P&L metadata stays unknown.

Before migration, Research & review hides and spot execution follows the original engine. Deploying source alone does not silently start charging fees. On release, apply migration first, then deploy this branch only after approval. Rolling source back after fee-bearing trades is not a safe accounting rollback: retain the compatible cost engine/ledger or reconcile those new executions. Do not drop journal/fee columns or restore an old balance snapshot blindly.

## Reproducible checks and remaining limits

`node scripts/check-research-costs.mjs` starts and stops a disposable local PostgreSQL cluster with synthetic identities/accounts. `--production` runs the same suite against the generated live-named schema on that disposable server. On Linux set `PG_BIN=$(pg_config --bindir)`; Windows defaults to PostgreSQL 17’s installed bin directory. No database URL, secret, private snapshot or production account data is consumed. Checks cover repeatable migration preservation, zero/nonzero costs, net round trips, insufficient funds, concurrent retries, freshness/session checks, post-placement observations, after-cost limit bounds, owner isolation, append-only plans/reviews, no-trade links, reset and deletion preservation. CI runs both suites, TypeScript and a build using placeholder config. The older full Neon suite still requires a private migration snapshot and is not a substitute for these self-contained checks.

The quote guard already rejects provider observations older than five minutes/future by over one minute, enforces instrument/currency type and regular session for non-crypto. The added SQL wrapper rechecks time after network/transaction delays. Limit fills additionally reject observations predating order placement. Quotes can still be delayed and are last-trade observations, not executable bids/asks. No liquidity, queue priority, partial fills, settlement, dividend credit, corporate actions, exchange calendar guarantee or guaranteed background schedule is modeled. Configured costs are assumptions, not a claim of real execution fidelity.
