# Existing stock LONG/SHORT positions through MCP

Stock/ETF LONG/SHORT tickets already use the shared `fx_positions` margin engine. This change removes the accidental forex-only MCP account restriction, rather than creating a stock engine. Existing tool names remain compatible: `open_forex_position` and `place_forex_entry_order` accept matching stocks/ETF or forex accounts. Crypto accounts still require `open_crypto_position` and its existing guardrails. Token checks, owner scoping, server quotes, SQL validation and retry IDs remain authoritative.

`get_transactions` is the spot/cash ledger. Use `list_forex_positions` for margin positions, with optional `status: open | closed | all` (default open) and `limit` (default 50, max 200). It exposes direction, entry/close prices, SL/TP, opened/closed timestamps, deadline, holding minutes, and recorded exit reason. Existing aliases `rate`, `stopLoss`, and `takeProfit` remain. Holding minutes measure elapsed clock time, not trading days. Pending-order expiry is separate from a position's holding deadline.

The shared open card and closed stock/forex history display protection and deadlines. Page timer checks now use the atomic automatic-check path, rather than manual close. The SQL engine records `manual`, `timer`, `sl`, `tp`, or `stopped` separately from status; partial closure slices retain SL/TP and deadline information. Scaled take-profit slices record TP. Historical generic `closed` rows remain unknown instead of being relabeled from a timestamp guess. Legacy explicit SL/TP/stop-out statuses remain readable. Older records without a saved holding duration can derive an approximate duration from their current opened/deadline timestamps; this does not reconstruct an earlier timer setting.
